# 05 全功能清单与优先级

## 优先级定义

| 级别 | 定义 | 判定标准 |
|---|---|---|
| **P0** | 产品成立的必要条件 | 缺失则无法发布 |
| **P1** | 显著影响体验或竞争力 | 首个正式版应具备 |
| **P2** | 增强功能 | 后续迭代 |
| **P3** | 探索性 | 不定排期 |

## 功能取舍说明（重要）

### 为什么音频是 P2

远程桌面 90% 的场景是办公（写代码、看文档、运维），音频不是核心价值。而音频采集在三平台的复杂度不低（WASAPI loopback / PulseAudio monitor / CoreAudio tap），**且音频会与视频争夺带宽与线程**，早期引入会干扰延迟优化。

### 为什么文件传输是 P1 而非 P0

它是「有了更好」而非「没有就不成立」。RustDesk 用户的核心抱怨是流畅度，不是文件传输。**先赢延迟，再补功能。**

### 为什么服务端是 P1

M1–M3 全部可用「手动输入 IP:端口」完成直连验证，不需要任何服务端。服务端只在需要「跨公网自动连」时才必要。**先把单机链路做对，再做网络。**

### 明确不做的功能

| 功能 | 理由 |
|---|---|
| 远程唤醒局域网（WoL 深度集成） | 网络环境依赖强，收益低 |
| 游戏专用模式（120fps+） | 与办公定位冲突，P3 探索 |
| 虚拟显示器驱动 | 需内核驱动，签名成本高 |
| 多用户同时控制同一被控端 | 会话模型复杂度激增 |
| 移动端 | 人力与验证成本过高 |
| 免安装 Web 服务端管理 | 与零知识设计冲突 |
